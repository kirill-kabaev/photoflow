# Natural Skin Retouch, Spot Healing и Smart Crop

Дата: 16.11.2026. Локальная реализация без новых зависимостей, моделей, API или upload.

## Что реализовано

- Natural Skin Retouch для новых планов по умолчанию: tone_evenness=0.12,
  redness=0.04, только внутри semantic face_skin. Корректируется медленное цветовое
  поле; яркостная фактура сохраняется. Тёмные отметки и сильные границы защищены.
  `enabled=false` отключает эффект; исторические рецепты не переинтерпретируются.
- Spot Healing выключен. Консервативный детектор ищет выраженные компактные
  красноватые области на нескольких масштабах, проверяет локальный контраст,
  шум и форму. Confidence — эвристическая оценка признаков, не вероятность акне.
  Строго исключаются зоны глаз/век/бровей/губ/носа/волос и их окрестности.
- Обязательный визуальный отбор Codex перед предложением удаления; AI может
  отбросить любые или все кандидаты. Затем реальный overlay и индивидуальное
  `Potential pimples detected. Remove them? Yes / No`. Отсутствие ответа не согласие.
- Только Yes разрешает локальный перенос соседней текстуры, радиус до 8 px,
  с проверкой цели/донора. В новой версии сохраняются согласие, координаты донора,
  настоящий 100% before/after лица до/после удаления при одинаковом grade.
- Smart Crop: визуальный анализ Codex, два варианта 16:9 и 9:16, рекомендация,
  override среди безопасных вариантов и keep original. Без выбора нет нового crop.
  Защищённые AI регионы ограничивают integer geometry; невместившийся вариант
  остаётся диагностическим. Координаты привязаны к ориентированному RAW.
- Точный native pixel box выполняется без ресайза/растяжения и воспроизводится в
  approval-gated экспорте. Маски и healing остаются в исходных координатах до crop.
  Все операции сохраняют бюджет, историю версий и отдельное одобрение экспорта.

## Использование

```bash
photoflow direct SESSION --next --semantic --smart-crop
photoflow crop-propose SESSION PHOTO --file /tmp/actual-visual-analysis.json
# После настоящего показа и выбора пользователя:
photoflow crop-decision SESSION PHOTO --request ID --choice '9:16' --by USER \
  --message 'ACTUAL USER RESPONSE' --shown-sha256 PROPOSAL_SHA
photoflow direct SESSION --resume
```

`skin-preview SESSION PHOTO --version v007` и `spot-scan` не декодируют RAW заново.
`spot-review --keep ... --reason ... --inspected-sha256 ...` только отбрасывает
кандидаты после фактического осмотра. `spot-decision` фиксирует реальный Yes/No.
По умолчанию старый Director без `--smart-crop` сохраняет прежний порядок шагов.

## Проверки и ограничения

Автотесты — offline/synthetic, включая batch из пяти фиктивных RAW, отдельные Yes/No,
ложные срабатывания, 13 чувствительных facial-классов, отсутствие ответа, stale/tampered
согласия, неизменность пикселей вне healing, native crop mapping, точные ratios при
разных ориентациях/нечётных размерах, бюджет и экспорт только одобренной версии.
Реальные новые фотографии для тестов не обрабатываются; RAW integration исключена.
**175 passed, 3 deselected** (`pytest -q -m 'not raw'`). Проверены SHA всех
**72 RAW**, **10 исторических версий / 322 immutable artifacts**. Queue, render budgets
и processing cycles совпали со снимком до реализации. Новых full versions: 0;
одобрений фотографий/экспортов: 0.
[Локальное свидетельство](../sessions/portrait_01/reviews/skin_healing_cropping_verification.json).

Детектор намеренно может пропускать слабые/некрасные дефекты; он не умеет надёжно
классифицировать постоянные особенности кожи. Модельные границы грубее RAW и требуют
визуального контроля. Nose healing исключён целиком. Качество реального healing
не заявляется: пользователь не давал Yes. Для crop требуются корректные protected
regions от настоящего визуального анализа; это не новая нейросеть композиции.
Предложения строятся из существующего полного preview; уже кадрированную версию
нужно заменить для анализа доступной некропнутой версией. Выбор ratio сам по себе
не разрешает новый цикл full render или финальный экспорт.
