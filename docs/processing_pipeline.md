# Pipeline обработки и цвета

## RAW и нейтральная база

rawpy/LibRaw открывает оригинал только для чтения. AHD демозаика, black/white levels
из LibRaw, ориентация из RAW без ручного повторного вращения. Neutral baseline:
WB камеры, `highlight_mode=clip`, `output_color=sRGB`, `gamma=(1,1)`,
`output_bps=16`, `no_auto_bright=True`, `bright=1.0`. Далее uint16 → float32 / 65535.

LibRaw выполняет camera→sRGB color conversion. Рабочее пространство — линейный
sRGB с D65 primaries, не AdobeRGB/ProPhoto. Это практический ограниченный gamut.
Отсечённые декодером цвета/света на последующих шагах не восстанавливаются.
Highlight blend/reconstruct включаются только рецептом и ограничены LibRaw.

WB рецепта: camera, daylight или custom из четырёх RAW-множителей [R,G,B,G2].
Это не Kelvin/tint и не имитация Lightroom. `use_auto_wb=False` всегда;
экспозиция применяется только в Python. Нейтральная база остаётся неизменной
даже при custom WB результата. До/после получают одинаковый crop.

Параметры сверены с [rawpy Params](https://letmaik.github.io/rawpy/api/rawpy.Params.html)
и проверены на установленном rawpy 0.26.1 / LibRaw 0.22.0, Sony ARW.

## Порядок глобальных операций

1. Exposure: `linear_rgb *= 2**EV`, диапазон −3…+3.
2. RGB gains: независимые множители 0.75…1.25. Это явная художественная RGB-коррекция,
   не дополнительный скрытый white balance.
3. Highlights: Y'=Y/(1+h*max(Y−0.5,0)), h=0…1; RGB масштабируется по Y'/Y.
   Это compression, не восстановление отсутствующих данных.
4. Shadows: `rgb *= 2**(s*(1−clip(Y/0.25,0,1)))`, s=−0.5…+0.5.
5. Black/white points: `(rgb−black)/(white−black)`. Диапазоны black ±0.05,
   white 0.8…1.2, в единицах линейного диапазона 0…1.
6. sRGB transfer function: 12.92x при x≤0.0031308, иначе 1.055x^(1/2.4)−0.055;
   значения вне gamut [0,1] ограничиваются на этом этапе.
7. Display contrast: `(rgb−0.5)*(1+c)+0.5`, c=−0.5…+0.5.
8. Display tone curve: монотонная кусочно-линейная интерполяция контрольных точек.
9. Saturation: масштаб цветового отклонения от серого; vibrance — документированное
   приближение с множителем `saturation+vibrance*(1−(max(rgb)−min(rgb)))`.
   Использование Rec.709 весов в display RGB — приближение, не физическая яркость.
10. Denoise: очень ограниченная гауссова фильтрация с весом по локальному перепаду.
    Глобальная сила ≤0.3. Это не AI denoise и не доказанное сохранение каждой поры.
11. Sharpen: unsharp sigma=1 px, ограничение high-pass ±0.08, сила ≤0.5.
12. Обратная sRGB transfer function → float32 linear RGB.

Клиппинг до и после отражается в метриках; после локальных коррекций возможны
значения выше 1 и ниже 0, обрезаемые при выводе. Намеренные изменения не назначаются
эвристически: всё управление идёт из рецепта.

## Локальные операции

Маски — эллипсы в **ориентированном исходном кадре до crop**, координаты [0,1].
Центр и радиус масштабируются независимо по ширине/высоте, пиксель оценивается в
его центре. Smoothstep внутри границы формирует растушёвку. `feather` — доля
радиуса, >0…1. Маски сохраняются как float32 `.npy` без pickle; overlays — sRGB JPEG.

Применение идёт в порядке списка masks; операции одной маски — в порядке
local_adjustments. Маски создаются по одной для ограничения памяти.

- exposure: `rgb *= 2**(amount*mask)`, amount ±0.75 EV.
- redness: уменьшается только положительное R−G на силу 0…0.3 с компенсацией
  зелёного канала для сохранения Y. Это ограниченное уменьшение красного избытка,
  не определение кожи, не универсальная коррекция magenta/green.
- saturation: `rgb += (rgb−Y)*amount*mask`, amount ±0.3.
- sharpen: локальный capped high-pass ±0.04, сила 0…0.5.
- smooth: сдержанная фильтрация с весом по перепаду, сила 0…0.25.

Нет геометрической реконструкции, генеративной дорисовки или автоматического healing.
Эллипсы могут задевать волосы/губы: Codex обязан осмотреть overlays. Качество пор
проверяется при 100%, а не по общим метрикам. Семантическая модель — следующий этап.

## Crop, previews и экспорт

Crop — доли исходной ширины/высоты, границы округляются вниз к пикселю;
пустой crop отвергается. Before/after используют одну область и ориентацию.
Превью: float resize Lanczos, затем sRGB и uint8; длинная сторона ≤1400.
Сравнение: две картинки одинакового размера и строка 32 px с BEFORE/AFTER.

Экспорт обрабатывает оригинал в полном разрешении, применяет sRGB OETF один раз
и квантует JPEG в 8 бит, TIFF — в 16 бит/канал RGB. TIFF без сжатия (lossless),
JPEG subsampling=0 и quality из рецепта. В оба файла встраивается профиль sRGB,
созданный [Pillow/LittleCMS](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html).
TIFF пишется [tifffile](https://pypi.org/project/tifffile/), ICC tag 34675.
Проверяются размер, RGB-интерпретация, uint16 и соответствие ICC ожидаемому sRGB;
timestamp и profile ID исключаются из бинарного сравнения профилей.
Время создания ICC может отличаться между процессами; байтовая идентичность JPEG
из-за заголовка профиля не гарантируется. Полный camera EXIF пока не переносится.
