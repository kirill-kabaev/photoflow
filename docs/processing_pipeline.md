# Pipeline обработки и цвета

## RAW и нейтральная база

rawpy/LibRaw открывает оригинал только для чтения. AHD демозаика, black/white levels
из LibRaw, ориентация из RAW без ручного повторного вращения. Neutral baseline:
WB камеры, `highlight_mode=clip`, `output_color=sRGB`, `gamma=(1,1)`,
`output_bps=16`, `no_auto_bright=True`, `bright=1.0`. Далее uint16 → float32 / 65535.

LibRaw выполняет camera→sRGB color conversion. Рабочее пространство — линейный
sRGB с D65 primaries, не AdobeRGB/ProPhoto. Это практический ограниченный gamut.
Отсечённые декодером цвета/света на последующих шагах не восстанавливаются.
Highlight blend/reconstruct включаются только рецептом и ограничены LibRaw.

WB рецепта: camera, daylight или custom из четырёх RAW-множителей [R,G,B,G2].
Это не Kelvin/tint и не имитация Lightroom. `use_auto_wb=False` всегда;
экспозиция применяется только в Python. Нейтральная база остаётся неизменной
даже при custom WB результата. До/после получают одинаковый crop.

Параметры сверены с [rawpy Params](https://letmaik.github.io/rawpy/api/rawpy.Params.html)
и проверены на установленном rawpy 0.26.1 / LibRaw 0.22.0, Sony ARW.

## Порядок глобальных операций

1. Exposure: `linear_rgb *= 2**EV`, диапазон −3…+3.
2. RGB gains: независимые множители 0.75…1.25. Это явная художественная RGB-коррекция,
   не дополнительный скрытый white balance.
3. Highlights: Y'=Y/(1+h*max(Y−0.5,0)), h=0…1; RGB масштабируется по Y'/Y.
   Это compression, не восстановление отсутствующих данных.
4. Shadows: `rgb *= 2**(s*(1−clip(Y/0.25,0,1)))`, s=−0.5…+0.5.
5. Black/white points: `(rgb−black)/(white−black)`. Диапазоны black ±0.05,
   white 0.8…1.2, в единицах линейного диапазона 0…1.
6. sRGB transfer function: 12.92x при x≤0.0031308, иначе 1.055x^(1/2.4)−0.055;
   значения вне gamut [0,1] ограничиваются на этом этапе.
7. Display contrast: `(rgb−0.5)*(1+c)+0.5`, c=−0.5…+0.5.
8. Display tone curve: монотонная кусочно-линейная интерполяция контрольных точек.
9. Saturation: масштаб цветового отклонения от серого; vibrance — документированное
   приближение с множителем `saturation+vibrance*(1−(max(rgb)−min(rgb)))`.
   Использование Rec.709 весов в display RGB — приближение, не физическая яркость.
10. Denoise: очень ограниченная гауссова фильтрация с весом по локальному перепаду.
    Глобальная сила ≤0.3. Это не AI denoise и не доказанное сохранение каждой поры.
11. Sharpen: unsharp sigma=1 px, ограничение high-pass ±0.08, сила ≤0.5.
12. Обратная sRGB transfer function → float32 linear RGB.

Клиппинг до и после отражается в метриках; после локальных коррекций возможны
значения выше 1 и ниже 0, обрезаемые при выводе. Намеренные изменения не назначаются
эвристически: всё управление идёт из рецепта.

## Локальные операции

Маски — эллипсы в **ориентированном исходном кадре до crop**, координаты [0,1].
Центр и радиус масштабируются независимо по ширине/высоте, пиксель оценивается в
его центре. Smoothstep внутри границы формирует растушёвку. `feather` — доля
радиуса, >0…1. Маски сохраняются как float32 `.npy` без pickle; overlays — sRGB JPEG.

Применение идёт в порядке списка masks; операции одной маски — в порядке
local_adjustments. Маски создаются по одной для ограничения памяти.

- exposure: `rgb *= 2**(amount*mask)`, amount ±0.75 EV.
- redness: уменьшается только положительное R−G на силу 0…0.3 с компенсацией
  зелёного канала для сохранения Y. Это ограниченное уменьшение красного избытка,
  не определение кожи, не универсальная коррекция magenta/green.
- saturation: `rgb += (rgb−Y)*amount*mask`, amount ±0.3.
- sharpen: локальный capped high-pass ±0.04, сила 0…0.5.
- smooth: сдержанная фильтрация с весом по перепаду, сила 0…0.25.

Нет геометрической реконструкции, генеративной дорисовки или автоматического healing.
Эллипсы могут задевать волосы/губы: Codex обязан осмотреть overlays. Качество пор
проверяется при 100%, а не по общим метрикам. Stage 2 добавляет semantic masks ниже.

## Crop, previews и экспорт

Crop — доли исходной ширины/высоты, границы округляются вниз к пикселю;
пустой crop отвергается. Before/after используют одну область и ориентацию.
Превью: float resize Lanczos, затем sRGB и uint8; длинная сторона ≤1400.
Сравнение: две картинки одинакового размера и строка 32 px с BEFORE/AFTER.

Экспорт обрабатывает оригинал в полном разрешении, применяет sRGB OETF один раз
и квантует JPEG в 8 бит, TIFF — в 16 бит/канал RGB. TIFF без сжатия (lossless),
JPEG subsampling=0 и quality из рецепта. В оба файла встраивается профиль sRGB,
созданный [Pillow/LittleCMS](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html).
TIFF пишется [tifffile](https://pypi.org/project/tifffile/), ICC tag 34675.
Проверяются размер, RGB-интерпретация, uint16 и соответствие ICC ожидаемому sRGB;
timestamp и profile ID исключаются из бинарного сравнения профилей.
Время создания ICC может отличаться между процессами; байтовая идентичность JPEG
из-за заголовка профиля не гарантируется. Полный camera EXIF пока не переносится.

## Детальный просмотр и проверка тональной передачи

`detail_regions` задаёт прямоугольники в ориентированном исходном кадре до crop.
Их границы переводятся в целые пиксели; смещение итогового crop вычитается явно.
Детали сохраняются из полноразмерных before/after float32-массивов, затем sRGB JPEG,
без upsampling и без чтения готового общего JPEG. Размеры native, координаты и
scale=1 записываются в region.json. Каждый detail-файл проверяется хешем версии.

Добавлены regression tests монотонности, нейтральности серой шкалы, clipping,
сохранения RGB ratios при highlight compression и порядка exposure → display curve.
Реальный RAW отдельно сравнивается с независимым LibRaw `gamma=(2.4,12.92)`.

Кривые применяются к каналам display RGB, поэтому могут менять насыщенность/оттенок;
это не luminance-only tone curve. Contrast центрирован на display=0.5: положительное
значение затемняет более тёмные области. Нельзя заменять им осмысленное освещение лица.
Значения вне gamut отсекаются до tone curve: высокая экспозиция может создать плато,
которое последующая кривая уже не разделит. Compression до этого отсечения способна
защитить часть светов, но не вернуть сенсорный/декодерный clipping.

Проверка реального DSC03037 не выявила ошибки gamma или скрытого размытия.
Алгоритмы коррекций сохранены: изменения рендеринга в кандидатах заданы рецептами.
Подробные доказательства и ограничения: [диагностика](./portrait_rendering_diagnosis.md).

## Оптимизированное выполнение без смены цветового результата

`RawCache` публикует read-only float32 linear RGB `.npy` вместе с валидированным
entry.json: source SHA, RawSettings, engine/library versions, decoder identity,
shape, dtype и pixels SHA. Source hash проверяется даже на hit; mmap не является
источником доверия сам по себе. Ключи разных WB/highlight modes не смешиваются.
Необходимая новая RAW-конверсия сохраняется для дальнейшего preview/full/export.
Никаких преобразований camera WB через приблизительные JPEG-фильтры нет.

Полный global pipeline выполняется блоками по 256 строк. Pointwise формулы и
порядок операций сохранены; для последовательных Gaussian denoise/sharpen берётся
halo до двух четырёхсигмовых радиусов. Внутренние края блока отбрасываются, реальные
границы изображения используют прежний reflect. Regression проверяет побайтовое
равенство whole-array и tiled результатов с обоими фильтрами и без них.
Глобальные временные массивы освобождаются до локальных масок, а базовое изображение
для overlays строится один раз, вместо повторного resize для каждой маски.

Explore сначала уменьшает проверенные linear pixels (максимум 1200 px, не больше
0.5 исходного размера), затем вызывает тот же process_pixels. Цветовые/тональные
операции те же, радиусы пространственных фильтров масштабируются относительно
полного пикселя. Это не обещает идентичность resize-after/nonlinear-after-resize;
поры, ореолы и границы масок проверяются на настоящем полном результате.

У DSC03037 v006 before/after/comparison и проверенные native детали совпали по
декодированным пикселям с историческим A/v002. Сравнивались существующие артефакты,
дополнительный полноразмерный рендер для этой проверки не запускался.
RenderAttempt резервируется до полного прохода, максимум два; прерывание не
возвращает слот. Исторические версии и full-resolution outputs не заменяются cache.

## Semantic masks Stage 2

Модель получает sRGB preview из нейтрального linear RAW после штатной ориентации
LibRaw; отдельный preview EV входит в cache identity. Модельный letterbox 512 сохраняет
aspect ratio. Удаление padding, перевод дискретных labels и alpha описаны в
[semantic_segmentation.md](semantic_segmentation.md). EXIF flip второй раз не применяется.

Recipe содержит отдельные `semantic_masks` и binding `segmentation.cache_key`.
Они используют те же local operations, что ellipse: exposure, saturation, redness,
sharpen, smooth. Новые глобальные формулы не добавлены. Операции сначала выполняются
на ellipses в прежнем порядке, затем на semantic masks в порядке их списка.
`intersect_ellipse` умножает model alpha на художественный градиент. Перекрытие
face и face_skin может намеренно суммировать EV; это явно записывается в recipe.

Alpha создаётся из общей low-resolution float32 cache по одной области на полный
RAW; Bilinear применяется к float alpha, Nearest — к predicted support. После resize
alpha ограничена support, поэтому движок не меняет пиксели вне выбранной моделью
области. Ошибки самих предсказанных границ этим не устраняются.
Image-guided filter с малым радиусом формирует только внутренний переход, без
широкого outward feather. Это не маттинг отдельных волос и не ретушь текстуры.

Полные semantic arrays не дублируются в каждой версии. Версия сохраняет cache binding,
segmentation.json с моделью/весами/конфигурацией/хешами, применённые overlays и
обычный manifest. При потере/повреждении cache выполнение/экспорт завершается явной
ошибкой; нет молчаливого ellipse fallback. Кэш нужен для дальнейшей воспроизводимости.

## Natural Skin, согласуемый Healing и точный crop

После существующих локальных операций, до crop: `natural_skin` корректирует только
низкочастотное цветовое поле внутри face_skin; яркостная текстура не фильтруется.
Затем, только при проверенном индивидуальном Yes, Spot Healing переносит небольшие
участки соседней реальной текстуры с мягким смешиванием. Глаза/брови/губы/нос и
тёмные различимые отметки исключаются. При сомнении операция отклоняется.

Legacy `crop` сохраняет прежнее округление. Новое `approved_crop` хранит точный
pixel box и размеры ориентированного RAW: ширина/высота кратны 16/9 либо 9/16.
Полный результат — точный slice float32 без resize; baseline, native details и
экспорт используют тот же box. Preview может округлиться на несколько уменьшенных
пикселей ради точного aspect ratio; это не изменение full-resolution координат.
Согласие проверяется при import/process/export и копируется в immutable manifest.
