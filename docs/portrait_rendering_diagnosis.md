## Почему v001 выглядела muted

Главная причина — художественно недостаточный рецепт, а не ошибка gamma.
В v001: exposure +0.7 EV, contrast 0.03, identity tone curve `[0,0]→[1,1]`,
highlights 0.15, shadows 0.10, saturation 1.0; только один face ellipse с +0.15 EV.
Для глаз/волос/рубашки отдельных коррекций не было.

Нейтральная линейная RAW-проявка и sRGB transfer сами по себе не дают коммерческую
тональную характеристику камеры/конвертера. Исправление WB и умеренный exposure
дали техническую основу, но лицо/ткань остались в нижних средних тонах. Яркий фон
повышал среднюю яркость всего кадра, скрывая проблему освещения человека.

В уменьшенном RAW-derived измерении v001 медиана Rec.709-weighted display RGB luma
в прямоугольнике лица — **0.35863**, фона слева/справа — **0.72606 / 0.89308**.
Это смешанные прямоугольники, а не точная skin/background segmentation и не баллы качества.
Кадр уже имеет значительный контраст «тёмный человек — светлый фон»; ему нужна
разработка полутонов человека, а не просто ещё более сильный общий contrast.

Display contrast в движке: `(x−0.5)*(1+c)+0.5`. Значения ниже 0.5 при положительном
c становятся темнее. При c=0.03 наклон меняется лишь на 3%, и лицо слегка темнеет.
Увеличение одного contrast без кривой/локального света дополнительно затемнило бы кожу
и волосы. Это ожидаемая семантика оператора, но прежний рецепт использовал её неудачно.

WB v001 улучшил исходный холодный вид, но оставил избыток magenta на фоне/рубашке.
В кандидатах сохранён этот RAW WB, а явные linear RGB gains уменьшают R/B относительно G.
Без серой карты это визуальная нейтрализация, не доказанная абсолютная калибровка.

## Абляция: compression не является основной причиной

Один оператор отключался при неизменных остальных параметрах v001. Измерение
сделано на каждом четвёртом пикселе нового RAW decode, с одинаковыми областями.

| Настройка | Медиана лица | Медиана правого фона |
|---|---|---|
| v001 | 0.35863 | 0.89308 |
| highlights=0 | 0.35863 | 0.91007 |
| shadows=0 | 0.35128 | 0.89308 |
| contrast=0 | 0.36322 | 0.88163 |
| без локального face exposure | 0.34671 | 0.89308 |

- Highlight compression в этой сцене не меняет медиану лица и лишь умеренно
  сдерживает светлый фон: обвинять её в мутном лице оснований нет.
- Shadow lift даёт лицу всего около 0.007 display-luma; это не чрезмерное уплощение.
- Старый face lift даёт около 0.012 display-luma — недостаточно для требуемого вида.
- Более заметное изменение требует осмысленной кривой и адресного света.

Локальное доказательство: `rendering_diagnosis/measurements.json` в рабочей папке кадра.

## Проверка цвета и алгоритмов

1. RAW декодирован в linear sRGB `gamma=(1,1)`, затем применён Python sRGB OETF.
2. Тот же RAW независимо проявлен LibRaw с `gamma=(2.4,12.92)`, теми же WB/AHD/16-bit,
   без auto-bright. Сравнение каждого четвёртого пикселя: mean absolute error
   **0.000009736**, maximum **0.000024769**. Различие соответствует точности 16-bit
   lookup/quantization, а не двойному применению gamma.
3. v001 повторно построена из полного RAW с прежним рецептом и сохранена как JPEG
   с теми же параметрами. Разница декодированных пикселей со старым after.jpg:
   **max=0, mean=0**. Старый preview действительно показывает результат pipeline.
4. Проверены монотонность grayscale ramp, отсутствие нового оттенка нейтральной шкалы,
   явный clipping, сохранение ratios RGB при highlight compression без отсечения,
   порядок linear exposure → display curve и отсутствие второго exposure/gamma.

**Математические алгоритмы RAW/цвета/тона не изменены**: диагностика не дала
доказательств дефекта, вызывающего мутный v001. В `imaging.py` добавлено только
сохранение native detail crops, не новый рендеринг или художественный автокорректор.
AST-сравнение с предыдущим коммитом подтвердило неизменность десяти существующих
функций RAW, transfer, tone/masks, preview и export.

Подтверждены ограничения существующего дизайна:

- Clip в LibRaw uint16 и clip перед display curve уже не обратить последующей кривой.
- Положительный display contrast может отсечь самые глубокие тени.
- Per-channel display curve может менять насыщенность/оттенок, она не luminance-only.
- Linear sRGB ограничен gamut sRGB; highlight compression не восстанавливает
  отсутствующие сенсорные данные. Это не полная имитация Lightroom/ACR.

Эти границы зафиксированы тестами и учтены при выборе параметров. Отсутствие ошибки
на одном Sony ARW не означает доказанную корректность всех камер и сценариев.

## Clipping и сохранность деталей

Из полноразмерных float32 metrics, доли всех пикселей (до финальной JPEG-квантизации):

| Версия | Хотя бы один канал ≥1 | Все каналы ≤0 |
|---|---|---|
| v001 | 0.00000699776 | 0 |
| A / v002 | 0.00000219161 | 0.00000007690 |
| B / v003 | 0.00000149952 | 0.00001384172 |
| C / v004 | 0.00000099968 | 0 |

B сохраняет более плотные глубокие тени и имеет небольшой black-clipping
(~0.00138% кадра, 360 пикселей); обещать сохранение каждого численного RAW-уровня
было бы неверно. В осмотренном кропе волос видимая структура остаётся различимой.
A имеет два полностью чёрных пикселя; C не имеет полного RGB black-clipping по этой
метрике. Sensor clipping эта статистика не измеряет. При приоритете открытых глубоких
теней выбирать A/C, а не самый плотный B. JPEG в любом случае не является RAW master.

## Оставшиеся ограничения

Эллипсы — не семантические skin/hair/clothing masks; overlays показывают, что они
могут частично захватывать фон или соседнюю область. Нельзя обещать точную изоляцию
каждой ресницы, пряди и воротника. Силы сдержанные, границы проверены визуально.
Нет серой карты/калиброванного экрана для абсолютной оценки кожи. Нет healing,
генерации или восстановления нерезкой исходной текстуры. Skin smoothing отключён.
Дальнейшие изменения — только после выбора пользователя; approve/export не выполнялись.
