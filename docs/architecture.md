# Архитектура

Реализован первый сквозной этап из [дорожной карты](./ROADMAP.md).
`MASTER_PLAN.md` остаётся полной спецификацией; README перечисляет отличия.

| Модуль | Ответственность |
|---|---|
| `cli.py` | CLI с JSON-ответами, сообщения об ошибках, блокировка всей команды |
| `models.py` | Закрытые Pydantic-схемы, диапазоны, ссылки масок, история очереди |
| `storage.py` | Безопасные пути, SHA-256, flock, atomic replace + fsync |
| `queue.py` | RAW discovery, стабильные ID, порядок, приоритеты и переходы |
| `imaging.py` | LibRaw, linear sRGB float32, коррекции, маски, профили и экспорт |
| `workflow.py` | Handoff Codex, версии, feedback, AI review, одобрение, recover |
| `reporting.py` | Анализ Markdown, отчёты версий и обзор съёмки |

AI отвечает за художественные решения; Python не определяет, что является лицом,
кожей, хорошим стилем или привлекательным результатом. Нет вызова Codex из подпроцесса.
Импорт плана — явная граница доверия: неизвестные поля, операции, версии движка,
невалидные диапазоны и ссылки отклоняются. Рецепт не содержит исполняемого кода.

## Очередь

Все состояния из спецификации присутствуют. Основной маршрут:

```text
pending → analyzing → ready → processing → review → approved → exporting → exported
                                           ↓
                                  revision_requested → ready
```

Ошибки операции переходят в failed с причиной и историей. prepare переводит в
analyzing до декодирования, но не объявляет AI-анализ завершённым. Imported plan
переводит в ready. Завершённая обработка даёт review, при этом AI review отдельно
помечен как pending. Приоритеты имеют причину и timestamp, исходный filename order
в queue сохраняется. next выбирает по priority и исходному порядку, failed виден в status.

## Файлы и транзакции

- Одна session-wide advisory flock на всю команду, включая RAW processing.
  Другой процесс немедленно получает понятную ошибку. Это Linux/WSL2 single worker.
- JSON: временный файл в той же директории, flush/fsync, atomic os.replace, fsync directory.
- RAW только открываются для чтения; checksum проверяется до/после операции.
- ID = очищенный stem + 12 hex SHA-256 имени; rename исходника не выполняется.
- Версия сначала строится в `.staging-vNNN`, затем публикуется rename в `vNNN`.
  Обязательные артефакты проверяются; queue обновляется после публикации.
- Манифест хранит source/recipe checksums, родителя, движок/библиотеки, AI,
  маски и хеши неизменяемых артефактов. Feedback, report и AIReview изменяемы отдельно.
- Прерванные staging сохраняются, номера никогда не переиспользуются.
- recover проверяет опубликованную версию и может закончить обновление queue;
  незавершённый staging означает failed, с понятным способом retry.
- Экспорт строится в `.export-vNNN`, затем публикуется hard link с запретом clobber.
  Манифест final записывается последним, является маркером завершённой группы.
  Экспорт нескольких файлов не является одной атомарной файловой операцией:
  при power loss возможны частичные final, они сохраняются для явного разбора.
- При обычном исключении частичные hard links, созданные текущей операцией,
  удаляются; чужие/предыдущие результаты не удаляются.

Симлинки не поддерживаются в session/RAW/work/final. Родительские компоненты и
идентификаторы проверяются. Это защита от ошибочных/небезопасных путей, не изоляция
от злоумышленника с правом параллельно менять файловую систему и игнорировать flock.

## Воспроизводимость

Версии сохраняют рецепт, AI-анализ, снимок session_style, параметры LibRaw,
метрики, float32-маски и манифест. Экспорт использует точный одобренный рецепт и
тот же набор версий библиотек. Намеренное редактирование истории/манифеста не
аутентифицируется криптографической подписью; это локальная рабочая папка пользователя.
Полная идентичность чисел на разных процессорах и версиях библиотек не обещается.
