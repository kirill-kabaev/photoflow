# Операционные инструкции PhotoFlow

`docs/MASTER_PLAN.md` — первичная техническая спецификация. Перед изменениями
прочитать её полностью. Дорожная карта и точные ограничения — в docs/ROADMAP.md
и README.md. Не считать существование модуля доказательством работоспособности.

## Неприкосновенные правила

- Никогда не записывать, не перемещать, не переименовывать и не удалять оригиналы
  в raw/. Обрабатывать только чтением; проверять SHA-256.
- Никогда не добавлять фотографии, sessions/, work/, final/, .env и ключи в Git.
- Никогда не выполнять Git push без явного разрешения пользователя.
- Не одобрять фотографии за пользователя. `approve --by` применять только после
  его явного указания версии. Демонстрации одобрения проводить на синтетических данных.
- Никаких web/GUI/server/БД-серверов и обязательных платных API.
- Не выдумывать AI-анализ, маски сегментации или результаты визуальной проверки.
- Не отправлять фотографии внешнему API без отдельного явного согласия.
- Не запускать shell/Python из рецептов; доступны только операции строгой схемы.

## Работа Codex как AI Director (Mode A)

Требования оптимизированного режима: `docs/tasks/AUTONOMOUS_PROCESSING.md`.
Для пользователя интерфейс — высокоуровневый разговор, а не ручное редактирование JSON.
Все художественные параметры выбирает Codex после настоящего осмотра изображения.

1. Для одного следующего кадра: `photoflow direct SESSION --next`. Для конкретного
   кадра: `direct SESSION --photo PHOTO`. `--batch` применять только по запросу
   обработать несколько кадров/оставшуюся съёмку. При начальной проверке DSC03037
   другие фотографии не обрабатывать.
   Для портретов с установленными локальными моделями использовать `--semantic`:
   сегментация выполняется/читается из кэша перед художественным анализом.
2. Следовать JSON `action` из Director. `analyze_and_plan`: осмотреть настоящий
   RAW preview/context/session_style, заполнить все 13 категорий `analysis.coverage`,
   создать полный Plan в запрошенном стиле. Не просить пользователя задать EV/WB/кривую.
3. Использовать максимум три небольших `explore`-кандидата по умолчанию. Смотреть
   реальные preview, выбрать лучший план; `import-plan`, затем `direct --resume`.
   Кэш — проверяемый linear RAW, а не JPEG для повторного фильтрования.
4. Полноразмерные попытки ограничены **двумя** (можно уменьшить до одной).
   Первая — полный план, вторая — только значимая адресная коррекция после осмотра.
   Прерванные/ошибочные попытки тоже расходуют слот; не сбрасывать render_attempts,
   не создавать новые run для обхода лимита. Исторические версии до введения
   счётчика сохраняются, но не пересчитываются задним числом.
   Новый явно запрошенный пользователем этап/переработка после завершения run может
   открыть `begin-cycle --by ... --reason ...`. Это отдельная аудируемая авторизация,
   не retry: прежние render_attempts не удаляются, новый цикл также ограничен 1–2.
   Никогда не открывать цикл автоматически ради обхода stop. Запрос Stage 2 прямо
   разрешил новую semantic-версию DSC03037 после исчерпанного прежнего бюджета.
5. `visual_review`: прочитать рецепт/style/метрики и действительно осмотреть before,
   after, comparison и релевантные native-кропы/overlays. Заполнить assessment,
   inspected_artifacts с фактическими SHA, best_version и selection_rationale.
   Нельзя утверждать осмотр пор/волос в 100% без suitable native detail crops.
6. При revise дать структурированные corrections: проблема, область, операция,
   ожидаемое улучшение, побочные эффекты, критерий проверки, adjustment_paths.
   Новый Plan меняет только эти параметры. После второго неудовлетворительного
   прохода остановиться и сообщить ограничения; сохранить лучший вариант.
7. Лучший вариант выбирается визуально среди доступных; новейший не считается
   лучшим автоматически. AI selection не является user approval.
8. `present_chat`: дать краткий русский отчёт (файл/съёмка/версия/стиль/статус,
   проблемы, изменения, качество, ограничения) и показать **реальные** before/after.
   В текущей среде доступен view_image → ImageContent; использовать его на
   before_after.jpg. Не считать Markdown-путь доказательством inline-рендера.
   Если изображения в клиенте недоступны, честно указать это, дать прямые ссылки
   и persistent Markdown. Не вызывать платный API и не генерировать замену фотографии.
9. Только после фактического показа: `presented SESSION --method tool_image_content`
   или `artifact_links`. Для batch продолжить `direct --resume` без промежуточных
   запросов одобрения. Это цикл внутри активного разговора, не фоновый запуск Codex.
10. `requires_user_input`: показать доступные реальные изображения, кратко объяснить
    художественную неоднозначность/неисправленный дефект/ошибку/отсутствующую функцию,
    задать один понятный вопрос без внутренних численных параметров.
    `--resume --resolution TEXT` только после реального решения пользователя;
    resolution не обходит лимит проходов.
11. Для feedback сохранять пользовательский текст; когда требуется полная
    неизменность старых файлов, использовать `revise --from-version VERSION
    --feedback-file PATH`. Снимок хранится отдельно и копируется в новую версию.
12. Только по явному запросу пользователя: approve точной версии, затем export.
    Итоговый delivery export по уже одобренному рецепту — не художественная итерация;
    он по-прежнему строится из RAW и запрещён без approval.

## Локальная семантическая сегментация Stage 2

- Инструкция и лицензии: `docs/semantic_segmentation.md`. SCHP ATR + BiSeNet R18,
  CPU ONNX по умолчанию; `segment --device auto` разрешает доступный CUDA provider
  с fallback CPU. Ни фото-upload, ни inference download не выполняются.
- Модели хранятся в игнорируемом `.models/` или `PHOTOFLOW_MODEL_DIR`. Установка —
  только явным `scripts/install_segmentation_models.py --download`; исходники/веса
  сверяются с закреплёнными SHA. Драйверы и WSL-настройки не менять.
- Для object-specific коррекций предпочитать semantic_masks по имени региона.
  Ellipse сохранять как художественный свет, при необходимости пересекать с semantic.
  Сохранять cache_key в recipe, осматривать реальные overlays и native boundary crops.
- Нельзя подменять отсутствующий/ошибочный semantic mask эллипсом без объяснения.
  Отсутствующие классы/ненадёжная facial parsing явно видны в diagnostics.
  `face` — coarse область, `face_skin` — BiSeNet с исключением глаз/губ/бровей.
- Model input 512 не даёт точного matting отдельных волос/пальцев. Native overlay
  показывает координаты применения, а не новые нейросетевые детали в 26 Мп.
- Сегментация не расходует полноразмерную попытку; её кэш повторно используется
  в exploration/full/correction/export. При отсутствии моделей — честная ошибка,
  не фиктивный inference. Старый elliptical-only CLI остаётся совместимым.

API Mode B и генеративная ретушь не реализованы. Не подменять их фиктивными провайдерами.

## Разработка и проверка

- Python 3.12, src layout; запускать `.venv/bin/python` и `.venv/bin/photoflow`.
- Публичные мутации сессии выполнять под `Session.lock()`; JSON через atomic_write.
- Не заменять старые версии; сохранять манифесты, checksum и параметры библиотек.
- Тесты — pytest; обычные тесты offline, synthetic decoder/test_fixture явно обозначены.
- После изменений запускать релевантные тесты. Для RAW — отдельный тест с
  `PHOTOFLOW_RAW_SAMPLE=...`; не называть synthetic fixture настоящим RAW/AI.
- После логически завершённого изменения с прошедшими тестами проверить diff и
  создать локальный коммит. В текущем sandbox `.git` read-only; рабочая альтернатива:
  `git --git-dir=.photoflow-git --work-tree=. ...`. В обычном клоне использовать Git как обычно.
- Сохранять репозиторий работоспособным после этапа; документировать незавершённое.
- Не добавлять пустые модули, зависимости и заявления о функциях без проверки.

## Natural Skin, Spot Healing и Smart Crop

- Новые планы включают `natural_skin` по умолчанию при импорте/explore. Это слабая
  коррекция низкочастотного цвета внутри реального `face_skin`, без фильтрации
  яркостной текстуры. Выключение: `natural_skin.enabled=false`. Исторические рецепты
  без поля сохраняют прежний результат; ревизии наследуют настройку родителя.
  При отсутствии semantic face_skin сообщать `unavailable`, не подменять маску.
- `spot_healing_visual_review`: осмотреть настоящий native face crop и overlay.
  `spot-review --keep ... --reason ... --inspected-sha256 ...` может только отбрасывать
  сомнительные точки; пустой список допустим. Нельзя выдумывать визуальный осмотр.
  Детектор — консервативная локальная эвристика, не модель диагностики акне.
- `spot_healing_decision`: обязательно сообщить о возможных точках, показать реальную
  разметку и спросить **"Potential pimples detected. Remove them? Yes / No"**.
  Только после настоящего ответа: `spot-decision --answer Yes|No --by ...
  --message ... --shown-sha256 ...`. Молчание, общий feedback и выбор crop не являются Yes.
  Для batch требуется отдельное решение по каждому фото. No продолжает обычный цикл.
- Yes разрешает только показанные точки и неизменный grade; удаление занимает один
  из оставшихся full-pass слотов, не открывает цикл. При отсутствии безопасного
  донора/маски/бюджета остановиться. После удаления показать `healing/before_after.jpg`
  с настоящим 100% лицом. Решение об удалении не одобряет фото или экспорт.
- Smart Crop включать `direct --smart-crop` при запросе кадрирования (совместимость:
  старый CLI без флага не запрашивает crop). `crop_visual_analysis`: визуально изучить
  фактический кадр, заполнить CropAnalysis, защитить голову/подбородок/кисти и важные
  детали. `crop-propose --file ...` создаёт только превью, без RAW-прохода.
- `crop_approval`: написать **Recommended crop: 9:16** (либо фактическую рекомендацию),
  показать original, 16:9, 9:16 и ограничения, спросить
  **"Which crop do you approve: 16:9, 9:16, or keep original?"**.
  Только настоящий выбор записывать через `crop-decision`; нельзя выбирать за человека.
  Невмещающиеся protected regions делают вариант диагностическим и запрещают применение.
- После выбора Director включает approved crop в новый план; источник координат —
  ориентированные RAW-пиксели, точное целочисленное 16:9/9:16, без растяжения.
  Экспорт использует тот же одобренный pixel box и отдельно требует одобрения версии.
- `skin-preview`/`spot-scan` работают по существующему native JPEG без новой RAW-версии.
  Честно обозначать источник такого demo; полный workflow применяет операции к linear RAW
  до JPEG. Новые фотографии в ходе реализации/preview-демонстрации не обрабатывать.
